## 领域知识

- CTF/夺旗解题类、红队评估类、渗透测试/风险挖掘类、1Day/NDay 验证类、代码审计类的探索先验完全不同，适用的经验范围也不同。
- 领域知识部分仅为历史经验沉淀，可能不适用于所有场景，仅供参考。

### CTF

#### 前置条件

CTF/夺旗解题类任务的默认前置信念：题目物料（题面、服务、二进制、协议、密文等）自含可解，突破口在题目物料本身。

#### 常见注意事项

- 否证实验（穷举、模拟、补丁对照）保留可复现脚本与算量记录，供后续探索引用边界。
- 动静态尝试均无效后，尝试组合已有信息，而不是武断的、无准确依据的给出全盘否定结论。
- 解题过程中的关键信息（如密文、密钥表、程序体等）及时将内容或落盘文件路径记录为认知，供后续复用。

### 渗透测试/风险挖掘

#### 风险挖掘技巧

- 进行风险挖掘时，优先挖掘可能导致主机控制或数据泄露的风险，如 RCE、接口越权/未授权等。
- 进行接口的风险挖掘时，尽可能全量已知接口，不应该满足于仅挑选可疑接口进行测试，但是可以根据接口信息调整测试顺序。前端提取的请求格式与入参范围是接口风险挖掘的高价值信息。
- 谨慎的处理不可逆操作，如数据删除、接口写、创建业务对象等操作。
- 测试 SQLi 风险时， ORDER BY 可能是容易被忽略的点。

#### 组件/框架漏洞 Poc 获取途径

在进行 1Day 或 NDay 漏洞的验证时，不要仅将当前模型已知的漏洞信息作为组件漏洞测试的范围，模型已知漏洞可能过旧或不全，结合以下方式获取更全面的漏洞信息：

1. 如果 Pentest-Tools 环境可用（存在 /.is_pentest_tools_env 文件），则环境的 nuclei templates 中提供了最新的漏洞 Poc，存储在环境的 `/opt/nuclei-templates` 路径下，可通过 CVE 编号或 Vendor 名称进行检索。
2. Norns CLI 提供了 `websearch` 插件扩展子命令，在允许互联网访问权限的情况下，可用于从搜索引擎中检索带有相关关键词的网页。
3. 开源组件的 Github issue 中可能带有漏洞信息或未提供 Poc 的脆弱性线索，当模型已知信息、1 和 2 都无法找到漏洞时，可以尝试配合拉取的源码进行检索与挖掘。

此外，组件漏洞不仅仅限制在当前组件，组件本身的依赖包或框架也可以作为突破方向。

#### 凭据爆破技巧

密码构建：

- pentest-tools 环境内置了 Top1000、Top10000 等常见通用密码本
- 在 pentest-tools 环境内置常见通用密码无效时，可以尝试结合目标特征、通用常量、变形技巧、其他外部来源数据自行构造密码本。
  - 目标特征：资产信息中出现的企业名/厂商名/品牌/产品名/系统名/主机名/人名及其英文拼写等
  - 通用常量：特殊字符（@、!、#、$、_ 等）、特定数字串（123、123456、000 等）、年份（2000、2021、2022 等）或以上混用（@2023）等
  - 变形技巧：大小写、leet 转换、位置替换等
  - 其他外部来源数据：已获取的账密、特定业务编号等

凭据喷洒：

- 非常规端口服务（如业务 Web 服务、自定义端口服务等）的口令喷洒前，先小范围尝试，确认判定口径（认证失败、连接拒绝、锁定提示的区别），并以正例与负例小样本自检脚本后再批量执行；控制并发与节奏，避免触发账号锁定或服务宕机。
