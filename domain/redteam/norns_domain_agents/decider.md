
## 领域知识

### 技巧

以下为历史经验的沉淀，可能不适用于所有场景，仅供参考。

#### 漏洞挖掘

- 进行风险挖掘时，优先挖掘可能存在主机控制或数据泄露的风险。
- 进行接口的风险挖掘时，尽可能全量已知接口，不应该仅挑选可疑接口进行测试，但是可以对接口根据相关信息调整测试顺序。
- 谨慎的处理不可逆操作，如数据删除、接口写入等操作。
- 测试接口的 SQLi 风险时， ORDER BY 可能是容易被忽略的点。
- 进行弱口令或接口遍历的测试时，不要使用几个常见或随机的弱口令或变量，尝试变换模式、结合平台名称或使用密码本等方式尝试更多组合。

#### 资产测绘

- 在获取一个陌生的、未探索过的 Subject 时，你可以不急于按空闲并发数提供资产测绘、漏洞扫描、暴力破解等多个与任务有关的探索方向，而是优先派生一个或少量探索，用于获取基础信息，再根据结果展开后续探索，以保证生成的探索是高价值、有意义的。

### 组件/框架漏洞公开获取途径

在进行 1Day 或 NDay 漏洞的验证时，不要仅将当前模型已知的漏洞信息作为组件漏洞测试的范围，模型已知漏洞可能过旧或不全，结合以下方式获取更全面的漏洞信息：

1. Norns CLI 提供了 `websearch` 子命令，在有互联网访问权限的情况下，可用于在搜索引擎中检索带有相关关键词的网页
2. Norns Pentest 镜像的 nuclei templates 中提供了最新的漏洞 Poc，存储在容器的 `/opt/nuclei-templates` 路径下，可通过 CVE 编号或 Vendor 名称进行检索。
3. 开源组件的 Github issue 中可能带有漏洞信息或未提供 Poc 的脆弱性线索，当模型已知信息、1 和 2 都无法找到漏洞时，可以尝试检索与挖掘。

此外，组件漏洞不仅仅限制在当前组件，组件本身的依赖包或框架也可以作为突破方向。
